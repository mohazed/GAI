# 00 — Decision log

Every decision that shapes the build, with the reason. Decisions taken during the build itself (from P-01 on), every departure from this plan and every change to `PROMPTS.md` are in `10-build-log.md` (B-xx). Decisions are numbered so later sessions can cite them ("per D-07"). Reversible unless marked otherwise. Confirmed by Mohamed Zouad on 2026-09-26; the spec is `Gaza Accountability Index — Cahier des charges.md` at the repo root.

| ID | Decision | Reason | Reversible? |
|---|---|---|---|
| D-01 | **Authorship: signed, by Mohamed Zouad.** The site is maintained only by the author for now; a later hand-over to a media organisation (e.g. Zeteo) is possible. | A signed project gets more trust from journalists. | **No.** The spec is explicit: changing from signed to anonymous later is not defensible. A hand-over to an organisation is fine; going anonymous is not. |
| D-02 | **Name: "Gaza Accountability Index"** for v1. No domain yet; the site launches on the free `*.pages.dev` hostname and moves to a domain when one is bought. | The name is honest about v1 scope and searchable. If scope extends (Lebanon, West Bank) in v2.0, the name can carry "Gaza" as its origin the way "Doctors Without Borders" carries its history. | Yes, before launch. Costly after. |
| D-03 | **No live extraction pipeline, no LLM API key.** All events are researched, drafted and filed by Claude Code sessions (Opus 5.5) driven by the author, using the sources playbook. Every event still needs a primary document, an archived copy and a hash. | Author's constraint (budget, control). It also removes the largest attack surface: there is no bot that can publish. | Yes. The data model is identical to the spec's, so an automated drafter can be added later and would feed the same review path. |
| D-04 | **The dataset is files in git, not a database.** Events, sources, assessments, corrections and replies are YAML files in the public `data/` tree. The review queue is a GitHub pull request. Two review modes, chosen by the author (see `01-plan.md` §4): **full review** (the author reads every PR before merge, as spec §7 asks) or **sampled review** (Claude Code's second reading is the gate, the merge is automatic when CI passes, and the author spot-checks a 10 % sample of events per wave). | A frozen dataset needs no server. Git gives the audit trail, versioning, diffs and the corrections history for free, and it is what the spec asks for ("everything reproducible from the public dumps"). | Yes. A Postgres import of the files is a 50-line script if a live pipeline is ever needed. |
| D-05 | **Fully static site.** Next.js with `output: 'export'`. The public API is a set of pre-built JSON files under `/api/v1/...`. Share cards are PNGs rendered at build time. | Zero running cost, no server to attack, survives traffic spikes, can be mirrored anywhere (including the author's VPS) by copying a folder. | Yes. |
| D-06 | **Hosting: Cloudflare Pages free tier.** Nightly rebuild by GitHub Actions cron, which recomputes decay and passivity windows even when no event changed. The author's VPS is an optional mirror, not the primary. | Free, unlimited bandwidth, global CDN. The build logs in a public repo are themselves public evidence of how the numbers were produced. | Yes. |
| D-07 | **One TypeScript monorepo** (pnpm workspaces): `packages/schema`, `packages/scoring`, `packages/pipeline`, `apps/web`, plus `data/`, `methodology/`, `archive/`. | One toolchain; a single `Event` type shared from validator to page. No Python pipeline because there is no automated pipeline (D-03). | Yes. |
| D-08 | **Structured indicators are generated, not hand-written.** B1 (UNGA votes), B2 (UNSC vetoes), D1 (funding), A1 (SIPRI), A2 and C3 (Comtrade) are produced by scripts from tables in `data/structured/`. Hand-authored events are for everything else. | 193 countries × dozens of votes cannot be typed by hand without error; a generator is reproducible and the table is the evidence. | Yes. |
| D-09 | **Per-indicator assessment records** (`data/assessments/{ISO3}.yaml`) distinguish "checked, nothing found", "no data published", "not applicable" and "has events". Coverage is computed from them. | The spec's coverage bar and its "no data is not zero" rule are impossible to implement honestly without recording what was checked. | No, this is structural. |
| D-10 | **Israel and Palestine are excluded from the ranking**, with an explanatory note. The Holy See (observer) is included. 193 scored entities. | One is the party to the conflict, the other the affected party; scoring either on a scale of third-party conduct is meaningless and invites ridicule. | Yes. |
| D-11 | **Passivity penalty −15**, applied when a country has no scored event in B, C or D in the trailing 365 days. The methodology page publishes the ranking at −5, −15 and −25 so readers see its effect. | Spec proposal, kept. Publishing the sensitivity disarms the "arbitrary number" attack. | Yes, by methodology version. |
| D-12 | **Category E is tracked and displayed but unscored in v1.0**, labelled "experimental". A v1.1 vote can score it. | Most contested category, smallest cap, high risk for little gain. Tracking keeps the record; not scoring keeps the ranking defensible. | Yes, by methodology version. |
| D-13 | **Statements B9/B10 are scored**, with the spec's caps (+10 / −10). | Without them, about 120 states with no arms trade and modest aid have no positive path at all and the ranking degenerates into "arms exporters versus everyone". The caps keep words below deeds. | Yes, by methodology version. |
| D-14 | **Lebanon and West Bank conduct is tagged from day one and scored only by a v2.0 methodology release.** | Spec. Keeps v1 defensible while the data is ready. | Yes. |
| D-15 | **Licences: data and methodology CC BY 4.0; code MIT.** | Newsrooms can embed and fork without copyleft friction; attribution is what the project needs. | Yes, but relicensing is awkward once others have reused the data. Decide before the first public release. |
| D-16 | **Phase-1 mode.** The composite score is computed from day one but its display is gated by one flag (`NEXT_PUBLIC_SHOW_SCORES`). Until the author flips it, the site shows scorecards: events, sources, coverage, category subtotals as counts, no number, no ranking. | Spec §9: "facts with sources are hard to attack; a composite number invites a methodology fight on day one." | Yes, one line. |
| D-17 | **Languages: English and French at launch**, both produced and reviewed by Claude Code sessions. Right-to-left layout is tested from day one with a pseudo-locale; Arabic content is v1.1. | Spec. The audience is the international community: English and French are the two UN working languages, and French covers most of West and North Africa and the francophone press. Template-generated summaries make FR nearly free. No country is privileged in coverage, ordering or prose. | Yes. |
| D-18 | **Forms without a server.** Right of reply and lead intake use GitHub issue forms in the public repo plus a project email address. Accepted replies are filed as YAML and appear verbatim on the country page. | No backend, public by default, spam-resistant (GitHub login), and the exchange is itself part of the audit trail. | Yes. A hosted form can be added later. |
| D-19 | **No analytics at launch**, or Cloudflare Web Analytics (cookieless) if the author wants counts. No third-party scripts, no Google Fonts requests, fonts self-hosted. | Privacy is part of credibility; a site about accountability should not leak its readers. | Yes. |
| D-20 | **Map rendered as SVG with d3-geo from Natural Earth data**, not MapLibre with vector tiles. | No tile server, no vendor, prints well, tiny bundle, and country fill is all the map needs to do. | Yes. |
| D-21 | **Radar chart replaced by a five-row category dot plot** on the Compare page. | Radar charts distort area and are hard to read for five categories with different caps; dot plots on a shared axis are exact. | Yes. |
| D-22 | **Light theme only in v1.** | Fewer surfaces to get right; the white-paper-and-ink register is the brand. Dark theme is v1.1. | Yes. |
| D-23 | **Design register: editorial data journalism** (Our World in Data, Bellingcat, a broadsheet data desk). Specifics in `05-design-system.md`, including the explicit anti-slop rules. | Credibility comes from restraint. | Yes. |
| D-24 | **Archived documents are not stored in git.** For each source the repo keeps: the Wayback snapshot URL, the SHA-256 of the archived bytes, the retrieval timestamp, the byte count, and an extracted plain-text copy (`archive/text/`, capped at 200 KB). | Keeps the repo small and forkable while the hash still lets anyone verify the Wayback copy. A raw-file mirror on object storage is a v1.1 option. | Yes. |
| D-25 | **Every score is reproducible from a clone.** `pnpm build:data` must regenerate every output byte-for-byte from `data/` and `methodology/` for a given build date. Outputs are not committed (except frozen superseded versions); CI builds twice and fails on any difference, and the deployed `manifest.json` records the git SHA and a hash of every file so anyone can rebuild and compare. | This is the whole credibility claim in one test. | No. |
| D-26 | **Model and effort for build sessions: Claude Opus 5.5**, one session per prompt in `PROMPTS.md`, `/clear` between sessions. Data-filling sessions use web search and fetch tools only. | Author's choice. | n/a |

## Deviations from the spec, all documented on the methodology page

1. `GET /v1/scores?date=` becomes `GET /api/v1/scores/{YYYY-MM-DD}.json` (static files cannot read query strings). An index file lists available dates.
2. The spec's LLM extraction agents are replaced by Claude Code sessions with a human-run protocol (D-03). The two-reader check survives as a mandatory second pass in every data prompt.
3. The review UI is GitHub's pull-request diff (D-04).
4. Radar → dot plot (D-21); MapLibre → SVG (D-20).
5. Category E unscored (D-12); Israel and Palestine excluded (D-10).
6. Indicator A2 excludes HS 8802 (aircraft) unless a licence register or SIPRI confirms the military nature of the shipment, because HS 8802 is dominated by civil airliners. See `02-methodology-spec.md`.
